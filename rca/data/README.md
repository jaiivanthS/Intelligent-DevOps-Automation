# RCA datasets

Regenerate everything here with (platform running):

```bash
cd rca
python scripts/export_dataset.py --api http://localhost:8081
```

| File | What it is | Rows |
|---|---|---|
| `synthetic_training_dataset.csv` | Exactly the data `models/rca_model.joblib` was trained on: 500 synthetic incidents per cause (7 causes; seed 42; 70% standard, 30% hard cases) and 1,000 normal windows. Generated by `rca_engine/synthetic.py`. | 4,500 |
| `live_incidents.csv` | Real incidents from the running platform where a fault was deliberately injected, so the true cause is known. Includes what the model and the rule baseline predicted. | grows with each experiment |
| `live.jsonl` | The same live incidents with their full evidence: 30 minutes of metrics, top error logs, recent deployments, alerts, and the feature vector the RCA used. | as above |
| `live_campaign.jsonl` | Experiment log from `scripts/fault_campaign.py`, one line per fault-injection trial: fault and strength, time to first alert and to incident, RCA answer, rule answer, time to resolve after the fault stopped. Missed detections are kept. | one per trial |
| `raw/` (not in git) | Where the RCAEval public benchmark would go (about 5 GB). Not downloaded. | none |

**Honesty note:** synthetic accuracy is optimistic because the same generator made both the training and the test data. Report live and synthetic results separately.

## Labels

| Label | Meaning | Injected live with |
|---|---|---|
| `bad_deployment` | A new release introduced errors or latency | (needs a real faulty build) |
| `dependency_failure` | A downstream dependency (inventory-db) is unreachable | `dependency_failure: true` |
| `error_burst` | The application throws errors without a deploy or dependency fault | `error_rate` |
| `latency_degradation` | Requests got slow without CPU or dependency problems | `latency_ms` |
| `cpu_saturation` | The process is CPU-bound | `cpu_burn_ms` |
| `memory_leak` | Resident memory grows steadily | `memory_leak_mb` |
| `service_down` | Prometheus can't scrape the service at all | (stop the container) |
| `normal` | A healthy window (synthetic file only; used to train the anomaly detector) | none |

## Columns in both CSVs

`row_id`/`incident_id`, `label`/`true_cause`, and in the live file also `model_prediction`,
`model_confidence`, `rule_prediction`, `model_correct`, `rule_correct`, `alerts`, and
`features_source`. `features_source` is `as_analysed` when the features are exactly what
the RCA used at the time (preferred), or `re_extracted` when they were rebuilt from stored
evidence.

The 26 features, computed by `rca_engine/features.py` (the same code runs in training and
in the platform):

| Feature | Meaning |
|---|---|
| `err_now`, `err_max` | 5xx error ratio, latest and window maximum (0–1) |
| `err_delta` | Error ratio now minus its healthy baseline |
| `lat_now` | p95 latency now, in seconds |
| `lat_log_ratio` | log(p95 now / baseline): >0 means slower |
| `rps_log_ratio` | log(request rate now / baseline) |
| `mem_log_ratio` | log(memory now / baseline) |
| `mem_growth_per_min` | Memory growth slope, as a fraction of baseline per minute |
| `cpu_now`, `cpu_delta` | Process CPU in cores; change from baseline |
| `inflight_max` | Maximum concurrent in-flight requests |
| `dep_min` | Minimum of `dependency_up` over the window (0 = dependency was down) |
| `up_min` | Minimum Prometheus `up` (0 = service could not be scraped) |
| `log_error_lines` | log(1 + number of ERROR/WARNING log lines in 15 min) |
| `log_dependency_frac` | Share of error logs mentioning connection/dependency failures |
| `log_timeout_frac` | Share of error logs mentioning timeouts |
| `log_app_error_frac` | Share of error logs that are application failures |
| `mins_since_deploy` | Minutes since the last successful deployment (capped) |
| `recent_deploy` | 1 if a deployment finished within 20 minutes |
| `recent_rollback` | 1 if a rollback happened recently |
| `alert_errors`, `alert_latency`, `alert_saturation`, `alert_dependency`, `alert_availability` | 1 if an alert of that category fired (experiment ground-truth alerts are never used) |
| `missing_signals` | How many telemetry sources were unavailable (confidence is reduced) |
